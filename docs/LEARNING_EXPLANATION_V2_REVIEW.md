# 해설 다이어그램 v2 적용과 실제 검증

2026-09-16 · 로컬 Memoryz · 첨부된 「Memoryz 해설 다이어그램 기획 v2」 기준

## 적용한 학습 흐름

- 답을 선택한 뒤 별도로 제출한다. 정답은 짧게 확인하고 바로 다음 문제로 갈 수 있다. 오답·모름은 내 답과 정답을 구분하고, 이유 이해 → 선택적 이해 확인으로 이어진다.
- 이해 확인은 2개 선택지 중 선택 후 제출한다. PASS/FAIL/SKIP을 원래 풀이와 별도로 저장한다. 정답을 맞혀도 원래 오답 점수와 오답노트는 유지한다. 실제 원문으로 만들 수 없는 확인 문제는 제시하지 않는다.
- 설명은 글 해설과 원문에 연결된 도식을 함께 사용한다. FLOW/COMPARE/CAUSE/TIMELINE/GRAPH/TREE 렌더러를 구현했다. 원문 위치, 참조 노드, 표 구조, 그래프 값, 트리 순환을 검증하며 실패하면 글 해설로 전환한다.
- 노드를 누르면 근거 구간을 강조한다. 크게 보기에서는 원하는 내용을 바로 선택하거나 앞뒤로 이동하고, 닫으면 원래 풀이를 유지한다. 해설 길이는 명시적으로 선택하며 기본값은 기기에 저장한다.
- 가림 카드는 사용자가 가릴 부분을 고르고 미리 본 뒤 저장한다. 기존 이미지 가림 카드는 유지한다. 글 오답 카드와 도식 카드는 별도로 존재할 수 있지만 같은 문제의 도식 생성 재시도는 중복을 만들지 않는다.
- 이미 저장된 도식이 있으면 선택창 대신 기존 카드와 실제 복습일을 보여준다. 보관함에서는 원본 문제 제목으로 구분하며, 가린 복습 앞면에는 그 제목으로 정답이 새지 않게 한다.
- 오답노트는 재시도와 해설을 우선한다. 카드 선택은 ‘카드로 모으기’에서 명시적으로 연다. 지난 선택, 틀린 기록, 해설 뒤 확인 결과를 구분한다.
- 답안 제출에는 요청 ID를 보존한다. 응답을 잃어 같은 답을 다시 제출해도 같은 attemptId를 돌려준다. 서버는 다른 답을 같은 ID로 보내면 거부한다. 추가 해설은 8초 안에 응답하지 않으면 기존 해설과 수동 재시도를 제공한다.

## 기획을 그대로 옮기지 않은 부분

| 문제 | 적용 판단 |
| --- | --- |
| 빠른 답을 추측으로 판정 | 응답 시간은 기록만 한다. 학습 태도를 단정하지 않는다. |
| 강제 확인·자동 다음 문제 | 확인을 건너뛸 수 있으며 다음 행동은 직접 선택한다. |
| 확인 성공으로 처음 오답을 지움 | 원점수와 확인 기록을 분리한다. |
| 임의 관계·수치로 그림 생성 | 근거 검증을 통과한 구조만 표시한다. |
| 레거시 문장의 일반 비교표 변환 | 항상성과 글루카곤을 억지로 비교하는 사례가 재현됐다. 감사한 광종·성종 정책 규칙으로 제한했고, 일반 과목은 검증된 생성 메타데이터가 없으면 TEXT로 처리한다. 기존 rule 메타데이터도 새 규칙으로 다시 계산한다. |
| 정답 위치 고정 또는 단어만 겹치는 오답 연결 | 정책명이 확인되는 경우에만 연결한다. 서로 다른 왕의 정책이 섞인 선택지는 특정 노드로 단정하지 않는다. |
| 자동 카드 생성·복습일 약속 | 저장은 명시적이며 실제 카드 응답의 일정을 사용한다. |
| 신고 처리 기한 확약 | 제보 접수만 알린다. 확인하지 않은 처리 기한은 표시하지 않는다. |

## 실제 브라우저에서 확인한 경로

모든 조작은 로컬 Go API와 빌드된 프런트를 사용했다. 기존 사용자 탭과 별도로 검증 탭을 사용했다.

1. 고려 자료 6문제: 선택만으로 채점되지 않음 → 오답 제출 → 내 선택과 정답 분리 → 비교 도식 → 선택한 문장의 원문 강조 → 크게 보기 → 이전 내용 → Escape 닫기.
2. 이해 확인 단계에서 답을 선택한 뒤 새로고침: 단계·선택 복원. 제출 후 PASS가 보이지만 자동으로 다음 문제로 가지 않음.
3. 정답은 짧은 판정과 선택적 해설만 노출. 모름 응답은 별도 문구. 확인 오답은 근거를 보여주고 계속할 수 있음. 확인 건너뛰기도 다음 문항으로 진행.
4. 결과는 처음 점수 3/6, 별도 확인 1개 맞힘·1개 더 살펴보기. 처음 틀린 세 문항이 오답노트에 유지됨.
5. 오답노트에서 ‘해설 뒤 확인 완료’와 ‘확인 문제도 다시 살펴봐요’를 구분. 해설을 열지 않고 재시도하면 선택하지 않은 1/1 문제로 진입하며 뒤로 가면 목록으로 복귀.
6. 가림 선택·앞면 미리보기·명시적 저장 → 실제 복습일과 저장 영수증 → 학습 단계 복귀. 보관함에서 도식 카드 열기 → 숨겨진 앞면 → 정답 공개 → 평가 저장 완료. 다시 열면 기존 카드 보기로 진입하며 가림 선택/추가 저장을 요구하지 않음.
7. 390px 화면에서 비교표의 중복 ‘항목’ 열 제거 후 대상 25%/근거 75% 배치 확인. 검은 노드의 의미는 ‘정답 근거’로 표시. 가림 앞면에는 접근성 텍스트까지 정답이 나오지 않는 렌더 테스트도 수행.
8. 항상성 문항: 부적절한 자동 비교를 제거한 새 런타임에서 글 해설·원문만 표시되는 것을 확인.
9. 복습 완료 안내 오류 재현 및 수정: 첫 GOOD은 서버에도 정확히 10분 뒤로 저장되었으나 완료 화면이 오늘의 복습을 제외해 다른 카드의 이틀 뒤 일정을 표시했다. 오늘의 분 단위 복습을 포함하고 이번 세션에서 평가한 카드만 집계하도록 수정했다. 실제 다음 평가 AGAIN의 ‘1분 뒤’ 버튼과 완료 화면 ‘1분 뒤 1장’이 일치했다.

## 자동 검증과 환경

- 프런트 전체 테스트, 타입 검사, 정적 프로덕션 빌드 통과.
- 6종 렌더/가림 DOM 검사, 잘못된 span·참조·구조의 음성 사례, 원점수/확인 분리, 재전송 집계, 당일 복습 안내 회귀 포함.
- Go 전체 테스트 통과. 별도 scratch DB에서 소유권 거부, 동시 재전송, 원점수 보존, 글/도식 카드 공존, 복습 후 재생성 시 복습일 보존, 제보 중복 방지, bootstrap 필드 검증.
- 실제 DB 주소가 loopback:15444/memoryz임을 확인하고 additive migration 00006만 적용했다. 기존 사용 데이터는 삭제하지 않았다. 소유한 Memoryz 프로세스만 재빌드·재시작했다.
- 검증 중 데모 문항 답안과 도식 카드 1장을 기록하고 해당 카드 복습을 두 차례 실행했다. 자동 시험 데이터는 scratch DB를 사용했다.

## 확인 범위

새로운 유료 모델 생성 요청이나 운영 배포는 하지 않았다. 생성 메타데이터의 스키마·파서는 fixture로 검증했고, 실제 UI에서는 기존 자료의 COMPARE와 TEXT 대체 경로를 확인했다. 나머지 도식의 구조/렌더 검증은 자동 시험이며 모든 과목 내용의 교육적 타당성이나 실제 학습 효과를 입증한 것은 아니다. GRAPH 수치 검증은 y=x, y=x², y=x³ 및 같은 f(x) 표기만 지원하고 나머지는 글 해설로 전환한다. 오프라인 캐시/큐 호환 검사는 자동 시험이며 실제 모바일 OS의 비행기 모드 검증은 포함하지 않는다.
