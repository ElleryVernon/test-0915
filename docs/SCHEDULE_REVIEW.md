## 데이터와 적용 범위

- `Schedule`의 필드(title · date · start · end · kind · subjectId · done), Prisma 스키마, 마이그레이션은 바꾸지 않았다. 바뀐 API는 두 곳이다. 첫째, `POST /planner/suggest`가 선택 입력 `after`를 받고 선택 출력 `reason`을 돌려준다. 둘째, `PATCH /schedules/:id`가 `subjectId: null`로 과목 연결을 해제할 수 있다. 예전에 저장된 `reason` 없는 추천 결과도 그대로 보인다.
- 고정 일정은 체크하지 않는다. 그래서 홈의 `다음 일정` 완료 수에서도 고정 일정을 뺐다. 빼지 않으면 지난 학교 일정이 영원히 미완료로 남는다. 진행 중인 고정 일정의 라벨은 `지금 할 공부`가 아니라 `지금 일정`이다. 예전에 완료로 표시된 고정 일정은 삭제하지 않았다. 시간표에서는 고정 일정으로 보인다.
- 빈 시간은 일정 사이와, 마지막 일정 뒤부터 공부 마감 22:00까지만 계산한다. 첫 일정 전(아침)은 빈 시간으로 만들어 내지 않는다. 일정이 하나도 없는 날은 빈 시간 행 대신 빈 상태 화면(학교 템플릿·추천)을 보여 준다.
- 추천 요청의 식별자에 `after`가 들어간다. 같은 날짜에 끝나지 않은 요청이 있으면 날짜로 찾아서 이어 보여 준다. 재시도와 이어 보내기는 원래 요청을 그대로 쓰므로 같은 날짜의 요청이 두 개 남지 않는다.
- 문서의 가짜 상태바와 홈 인디케이터는 구현하지 않았다. 헤더는 다른 탭과 같은 공통 64px `ScreenHeader`를 쓴다.
- 한국어 조사(과/와, 을/를, 으로/로)는 마지막 글자의 받침으로 고른다. 기존 배너의 `생명과학 개념 복습와` 같은 오류는 이제 생기지 않는다.
- 쓰이지 않게 된 `DateTimeField`와 `.schedule-gap`/`.schedule-time-range` 스타일은 지웠다.

## 후속 피드백 반영

- 학교만 있는 날은 빈 시간이 `일정 사이`에만 계산돼 채우기 CTA가 없었다. 목록 끝의 작은 `일정 추가 · 추천받기` 링크만 남아 위계가 약했다. 이제 저녁을 빈 시간으로 세서 `빈 6시간 채우기`가 주 행동으로 뜨고, `일정 추가`는 48px 보조 버튼이다.
- 학교가 16:00에 끝나는데 새 일정이 17:00부터 시작하던 문제를 고쳤다. 기본 시작은 첫 빈 시간이다(`defaultSlot()`).
- 채우기를 누르면 바로 로딩 시트를 열지 않는다. 그 대신 화면에서 진행 상황을 보여 준다. 토스트 `빈 시간에 맞는 공부를 찾고 있어요`를 띄우고, 채울 빈 시간 행에 주황 빛이 지나가는 효과와 `고르는 중`을 표시한다. 하단 버튼은 주황색 그대로 스피너와 실제 단계 문구(`빈 시간과 복습 카드를 보는 중 → 두 가지 안을 만드는 중 → 겹치는 시간이 없는지 확인하는 중`)를 보여 준다. 헤더 `+`, `일정 추가`, 빈 시간 행은 그동안 비활성화된다. 결과가 나오면 추천 시트가 열린다. 규칙 기반처럼 즉시 끝나도 0.9초는 진행 상태를 보여 준다. 실패하면 시트에 이유와 다시 시도 버튼이 나온다. `새로 추천받기`, `같은 요청 이어서 보내기`, `이전 요청 확인`을 누르면 시트가 닫히고 같은 방식으로 화면에서 진행된다. 시트 안의 로딩 화면은 없앴다(첫 요청을 일부러 실패시킨 뒤 다시 시도해서 확인, `retry-generating-390.json`). 화면에 다시 들어왔을 때 진행 중인 요청도 같은 방식으로 버튼에 표시된다. 스크린 리더에는 같은 문구를 상태로 알린다.
- 추천 실패 시트를 디자인 시스템에 맞췄다. 전에는 회색 박스 안에 시계 아이콘, 회색 버튼, 주황 버튼을 겹쳐 넣었다. 이제 제목은 무슨 일인지(`추천을 만들지 못했어요`), 부제목은 날짜, 본문은 공용 `ErrorNote` 알림으로 이유를 보여 준다. 그 아래 실패 종류에 맞는 주 행동 하나(`새로 추천받기` / `같은 요청 이어서 보내기` / `다시 확인하기`)와 `직접 일정 추가하기` 보조 버튼을 둔다. `이전 요청 확인`은 전달 여부가 불확실할 때만 나온다.
- AI 결과 중 블록 하나가 조건(25–60분, 겹침, 휴식, 시간대 등)에 어긋나면 전에는 추천 전체가 `학습 블록의 길이가 적절하지 않아요`로 실패했다. 이제 어긋난 블록만 빼고 나머지를 보여 준다. 한 안이 통째로 비면 같은 의도의 규칙 기반 안으로 채우고 `한 안은 규칙 기반이에요 · 조건에 맞지 않는 N개는 뺐어요`로 알린다.
- 홈 정렬: 카드 밖 콘텐츠를 카드 안 텍스트와 같은 선(390px에서 x=40)에 맞췄다. 해당 요소는 로고, 인사말, 날짜 줄, 다음 일정, 섹션 제목, 목록, 전체 보기다. 카드(복습·응원·자료 안내)는 x=20으로 바깥에 걸린다. 오른쪽 끝도 x=350으로 맞췄다(`home-390.json`에서 측정). 홈 일정 소요 시간은 `170분` 대신 `2시간 50분`으로 표시한다.

## 추천 시트 노출 규칙

2026-09-15 후속. 사용자 지적: "AI로 빈 시간 채우기를 누른 적이 있으면 탭을 바꿀 때마다 추천 시트가 열린다." 원인은 시간표에 들어올 때마다 아직 확인되지 않은 가장 최근 추천을 찾아 그 날짜로 옮기고 시트를 연 데 있었다. 확인 표시는 담기와 "둘 다 아니에요"에서만 남아서, X로 닫은 추천·실패한 요청·지난 날짜의 추천이 계속 되살아났다.

- R1 시간표에 들어올 때는 시트를 열지 않고 날짜도 바꾸지 않는다.
- R2 시트가 저절로 열리는 경우는 이번 방문에서 누른 요청의 답이 도착할 때뿐이다.
- R3 이전 방문에서 남긴 요청은 상태만 조회한다(다시 보내지 않는다). 도착하면 알리기만 하고 열지 않는다 — 그 날짜를 보고 있으면 토스트, 아니면 R4의 알림 줄.
- R4 아직 안 본 추천은 그 날짜 버튼이 "추천 보기"가 되고, 다른 날짜를 볼 때는 주간 줄 아래에 한 줄 알림("9월 17일 목 추천이 준비됐어요 · 보기")이 뜬다.
- R5 한 번 본 추천은 닫아도 남지만 저절로 다시 뜨지 않는다. 버튼 "추천 다시 보기"가 요청 없이 같은 추천을 연다. 담기나 "둘 다 아니에요"로 끝난다.
- R6 쓸모없어진 추천은 조용히 끝낸다: 지난 날짜, 담을 블록이 남지 않음, 오늘 추천 시간이 이미 시작됨, 그 사이 넣은 일정과 겹침. 버튼은 다시 "빈 N 채우기"가 되고 누르면 새로 추천한다.
- R7 실패하거나 접수를 확인하지 못한 요청은 들어올 때 알리지 않는다. 그 날짜에서 채우기를 누르면 기존처럼 실패 시트(새로 추천받기 / 같은 요청 이어서 보내기)가 열린다.

구현은 `src/components/social/planner-suggestion.ts`(순수 판정 `suggestionState`, 토스트 규칙 `readyToast`), `src/lib/ai-task.ts`(`seenAt` 기록과 보존, `listAiTasks`, `markAiTaskSeen`), 시간표 화면이다. 기기(IndexedDB)에 이미 저장되던 추천 기록을 그대로 쓰고 서버 계약은 바꾸지 않았다.

고정 일정 아이콘: 자물쇠는 "못 쓰게 잠긴 기능"으로 읽혀서 없앴다(시안의 `ic.lock`과 다르게 둔 것). 일정 종류는 아이콘 없는 대등한 두 칸 세그먼트이고, 시간표의 고정 일정은 테두리 카드와 오른쪽 `고정` 꼬리표로 구분한다. 보호자·계정 화면의 자물쇠는 실제 잠금·권한 의미라 그대로 둔다.

검증:

- `npx tsx --test tests/planner-suggestion.test.ts` 8개 통과. 변이 `node scripts/planner-followup-mutation.mjs`는 규칙 14개를 임시 복사본에서 하나씩 되돌려 모두 해당 테스트로 잡는다.
- 실제 브라우저 `npx tsx scripts/planner-followup-capture.ts`: 현재 빌드를 AI 키 없이 띄워(규칙 기반 추천, 유료 호출 0) 격리 qa-planner 계정으로 확인한다. 추천을 받고 닫은 뒤 학습 탭 → 시간표 탭, 새로고침에서 시트가 열리지 않고 오늘이 유지된다. "추천 다시 보기"는 새 요청 없이 열린다. 겹치는 일정을 넣으면 "빈 N 채우기"로 돌아가고 새 요청이 나간다. 응답을 붙잡아 둔 채 탭을 떠났다 돌아오면 시트도 토스트도 없이 알림 줄만 뜨고, 누르면 그 날짜와 시트가 열린다. 담으면 사라지고, 실패한 요청은 탭을 오가도 조용하다. 콘솔 오류 0, 가로 넘침 0, 자물쇠 0, 요청 4번.

## 검증

- `npm run typecheck` 통과. `npm test` 50개 통과, 실패 0. 새 검사는 지금 선·빈 시간·겹침 행 순서, 저녁 빈 시간, 새 일정 기본 시작, 지난 빈 시간 숨김, 고침 칩(줄이기·옮기기·하루 끝), 자율 학습만 세는 진행률, 조사, 월 달력, 최근 일정, 규칙 기반 추천의 빈 시간 배치·`after`·근거, AI 추천의 `reason`·`after` 검증, 홈의 고정 일정 제외다.
