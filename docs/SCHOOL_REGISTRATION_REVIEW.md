# 학교 시간 등록 개선

2026-09-16 · 로컬 학생 체험 공간. 앞선 시간표 집중 점검의 학교 등록을 이 흐름으로 대체한다.

- 학교 일정이 이미 있는 날에도 ‘학교 시간 등록’을 찾을 수 있다.
- 시작일 → 1주/4주 → 등교 요일 → 등교·하교 시간 → 날짜별 등록 미리보기 순서다. 1주는 시작일부터 7일이며 실제 종료 날짜를 표시한다. 지난 날짜는 선택하지 못한다.
- 시간을 바로 입력한다. `815`/`0830`/`08:30`을 받아 `08:15`/`08:30`으로 정리한다. 잘못된 시각과 등교보다 이른 하교는 등록하지 못한다.
- 월~일 중 실제 등교일을 선택하며 ‘월–금 선택’으로 빠르게 설정한다. ‘요일마다 시간이 달라요’에서 선택한 요일별 등교·하교 시간을 바꾼다.
- 등록 미리보기는 새로 등록할 날, 이미 같은 학교 시간이 있는 날, 다른 일정과 겹쳐 제외할 날을 구분한다. 충돌 일정의 이름·시간을 보여 주며 해당 날짜의 시간표를 열 수 있다.
- 창 닫기·새로고침 후 입력을 보존한다. 저장 전 최신 일정을 다시 읽고 기존 일정은 덮어쓰지 않는다. 같은 시간은 재등록 대신 등록한 시간표 보기로 이어진다. 일부 등록 뒤 실패하면 다음 시도에서 저장한 날짜를 건너뛴다.
- 등록이 끝나면 첫 등록 날짜로 이동한다. 사용자가 창을 닫고 다른 작업으로 옮겼다면 그 날짜를 강제로 바꾸지 않는다. 등록 도중 닫기는 완료 알림으로 이어지고 다른 학교 등록 진입은 진행 중으로 표시한다.

## 실제 조작 근거

1. 기존 학교 일정이 있는 9/17에서 등록 버튼을 열었다. 초기 9/17~9/23의 평일 5일 중 새로 3일·이미 등록 2일을 확인했다.
2. 등교 `815` → `08:15` 자동 정리. 기존 08:30–16:00 학교와 다른 시간을 입력하자 두 날짜를 충돌로 구분하고 원래 학교 시간을 표시했다. 하교 `730` → `07:30`은 사유와 함께 등록을 막았다.
3. 시작일 9/23, 1주, 수·금 등교, 수요일 08:15–14:30, 금요일 08:15–16:00, 이름 ‘학교 시간 점검’을 입력했다. 미리보기에 9/23과 9/25만 표시됐다.
4. 닫기 → 새로고침 → 재진입에서 기간·요일·다른 하교 시간·이름이 복원됐다. 390px 화면에서 직접 입력과 요일별 필드를 시각 확인했다.
5. 두 날짜를 실제 저장했다. 다시 열면 새로 0일·이미 등록 2일이며, ‘등록한 시간표 보기’는 새 요청 없이 9/23의 08:15–14:30 한 건으로 이동했다. 9/25에는 08:15–16:00 한 건이 있었다. 두 날짜의 빈 시간은 각각 14:30–22:00, 16:00–22:00이었다.

## 검증 범위

시간 파싱, 7일/28일·연도 경계, 요일별 시간과 토요일 선택, 중복/충돌/인접 시간, 잘못된 날짜·시각·빈 요일을 자동 검사했다. 전체 기존 회귀 검사·타입 검사·빌드도 통과했다. 실제 네트워크 장애 주입, 모바일 OS 숫자 키보드, 20일 일괄 저장은 수행하지 않았다.

검증으로 체험 공간에 `학교 시간 점검` 고정 일정 두 건(9/23 08:15–14:30, 9/25 08:15–16:00)이 남아 있다. 기존 일정 삭제·운영 배포는 하지 않았다.


## 시각·입력 컨트롤 후속 개선 (2026-09-16)

- 일정 추가 텍스트와 일정 표시 점을 그레이스케일로 정리. 오늘은 옅은 원과 테두리, 선택은 진한 원으로 구분한다.
- 기본 체크박스 대신 ‘매일 같은 시간 / 요일별 설정’ 두 가지 선택을 보여 준다. 전환해도 기존 요일별 입력을 유지한다.
- 학교 시작일은 폼 안에서 달력이 펼쳐진다. 누락됐던 공유 날짜 셀 스타일을 추가하고 44px 높이, 오늘/선택/비활성/키보드 포커스를 구분한다.
- 월 이동, 오늘 선택, 과거 날짜 제한, 방향키·Home·End 이동, Enter 적용을 제공한다. Esc는 펼친 달력을 먼저 닫고 날짜 입력 버튼으로 돌아간다.
- 390x844 실제 브라우저에서 월 이동 및 방향키/Enter로 10/2 선택 후 기간 갱신, 과거 날짜 비활성, Esc 복귀, 시간 모드 전환과 기존 입력 복원을 확인했다. 일반 일정 추가의 공유 달력도 선택 후 폼 복귀를 확인했다.
- 관련 ui-logic, school-schedule, social 테스트와 타입 검사·최종 빌드 통과. 운영 배포나 실제 기기 키보드 검증은 수행하지 않았다. 새 일정은 저장하지 않았고 검증 중 시작일 변경은 기존 9/23으로 복원했다.


## 숫자 정렬·등록 미리보기·이어쓰기 후속 개선

- Pretendard-Semibold의 실제 글리프 메트릭을 Next 번들 fontkit으로 측정했다. 17px의 tabular ‘16’은 잉크 중심이 박스보다 약 0.79px 오른쪽이고 proportional ‘16’은 중앙이다. 날짜에만 비례폭 숫자·자간 0·line-height 1을 적용했다. 시간과 수치 열의 기존 등폭 숫자는 유지한다.
- 기본 details 표시 대신 폼과 같은 제목·보조 설명·펼침 버튼을 사용한다. 날짜와 시간을 묶고 오른쪽 상태 배지로 등록 예정/이미 등록/겹쳐서 제외를 구분한다. 겹침 대상과 시간표 이동 링크를 제공하며 리스트 내부 스크롤을 제거했다.
- 작성 중인 일정은 별도 영역에서 상태, 제목, 날짜·시간, 이어쓰기 동작을 분리한다. 긴 제목은 2줄까지 표시한다.
- 동일 값 재선택은 초안을 생성하지 않는다. 새 초안에는 처음 입력값을 함께 저장해 원래 값으로 되돌리면 초안을 해제한다. 이전 형식의 초안은 보존한다.
- 실제 390px 브라우저에서 긴 제목 초안→닫기→새로고침→이어쓰기 복원→원래 빈 값 복귀 시 카드 제거를 확인했다. 등록 미리보기는 새6일·기존1일·충돌1일 혼합 상태로 확인했다. 검증 후 원래 학교 입력으로 복원했으며 신규 일정 저장은 없었다.


## 일정 추가 진입 통합

- 날짜 아래 학교 등록 버튼과 학교 등록을 따로 유도하던 안내를 제거했다. 빈 날짜도 ‘일정 추가’를 주 진입으로 사용한다.
- 일정 추가창 안에 ‘일정 / 학교 시간’ 탭을 둔다. 같은 등록창 안에서 패널만 바뀌며, 양쪽 입력은 유지한다. 기존 일정 수정창에는 신규 등록 탭을 노출하지 않는다.
- 실제 별도 검증 탭에서 일정 있는9/16·빈9/19 진입, 탭 왕복과 키보드 전환, 제목 및 학교08:10입력 보존, 브라우저 뒤로가기1회로 등록창 종료, 기존 학교 일정 수정 진입을 확인했다. 운영 반영이나 신규 일정 저장은 하지 않았다.

## 일정/학교 시간 시트 높이 후속 수정

- 일정 편집 시트는 공통 Sheet의 `adaptiveHeight` 옵션을 사용한다. 본문의 자연 높이와 헤더를 관찰해 높이를 갱신하고 240ms 전환을 적용한다. 최대 높이는 기존 화면 제한을 유지하며 초과 내용만 본문에서 스크롤한다. 전체 화면 및 다른 시트는 기존 크기 정책을 유지한다.
- 날짜 버튼과 학교 안내문이 차지하는 헤더 설명 영역은 같은 최소 높이를 사용해 탭 전환 시 헤더 내부 위치가 튀지 않게 했다. 시스템의 동작 줄이기 설정에서는 전환이 비활성화된다.
- 로컬 브라우저 390×844: 두 탭의 헤더 높이 92px, 탭 y=207.4px 동일. 최대 시트 높이 약759.6px에서 내부 스크롤 동작.
- 800×1200: 일정813px, 학교1073px로 내용에 맞춰 조절. 학교 달력 펼침 시 최대1152px와 내부 스크롤, Escape로 접으면1073px로 복귀. 전환 중1124px에서1073px 목표로 줄어드는 것도 관찰했다. 등록/저장은 실행하지 않았다.
- 관련 레이아웃·내비게이션·시간표·학교 등록 검사46개, 타입 검사, 정적 빌드 통과.
