# TypeSafe Jev 평가: 메모리즈의 판정 단계를 System One 모델로

2026-09-18. TypeSafe의 Jev(`jev-latest` = jev-1.13.0)는 텍스트를 생성하지 않고 **판정**만 돌려주는 모델이다: 예/아니오 확률(noul), 선택지 분포(choice), 순서 척도(score). 문서 기준 한 요청은 약 100 ms, 입력 토큰당 $0.042/M, 출력 무료, 요청당 64k 컨텍스트(상태 32k), 분당 1,200 요청. 고객 요청으로 학습하지 않는다고 명시한다. 한국어를 포함한 CJK를 받지만 정확도는 영어가 가장 좋다고 적혀 있다.

이 문서는 메모리즈에서 **생성이 아니라 판정**인 모델 호출을 골라 실제 API로 측정한 결과와 권장 사항이다. 스크립트는 `scripts/typesafe-eval.mjs`, 원자료는 `evals/university/*.json`(고정 채점 세트)과 `scripts/typesafe-eval/demo-items.json`(`go run ./cmd/demo-export`로 시드에서 뽑은 문항)이다. 키는 추적되지 않는 `.env`의 `TYPESAFE_API_KEY`에만 둔다. 제품 코드는 바꾸지 않았다.

## 지금의 모델 호출 중 무엇이 판정인가

현재 경로의 실측(기존 기록): 채점 한 호출 2.8~~4.07초(`docs/VERIFICATION.md` 23:41·06:05, `docs/UNIVERSITY_LEARNING_EVAL.md`), 채점+검수 최대 4호출·180초, 제품 경로 한 답안 12.9초·$0.00067(단일 표본). 생성 검수는 서술형 7.7~~23.9초, 객관식 3.5~11.6초. 공급자 시한 175초.

## 측정 방법

세 과제를 한국어 지시문(ko)과 영어 지시문(en)으로 각각 돌렸다. 상태(원문·질문·답안)는 모두 원래 언어(한국어 문항, 영어 교재 인용)다.

- **grade**: 고정 대학 채점 세트 12사례(개발 8 + holdout 4), 답안 64개(correct·short-correct·partial·misconception·keyword-only·prompt-injection). 답안마다 한 요청: 키워드별 choice(5상태) 4개 + 답안 유형 choice(reasoned/partial/keyword_list/central_contradiction/off_topic) + 채점 지시 삽입 noul. 점수는 상태 가중(1/0.5/0.15/0/0)과 유형 상한(keyword_list 20, central_contradiction 25, off_topic 0)으로 코드가 계산했다. 기대값은 세트의 답안 종류·점수 구간·exact keyword membership(correct·prompt-injection 전부, 일부 holdout 부분답).
- **quiz**: 시드 객관식 5문항, 원문만 주고 choice로 정답 보기 선택 + "정답이 하나로 확정되는가" noul. 정답표와 비교.
- **claims**: 사례별 `concepts`(원문이 뒷받침, 56개)와 `mustNot`(원문과 모순, 38개), 시드 서술형의 키워드(뒷받침)와 방해어(뒷받침 아님, 8개)를 supported/contradicted/says_nothing choice로 한 요청에 묶어 판정. 총 102개 판정.

전체: 입력 417,182 토큰, 추정 비용 **$0.0175**, 요청 p50 267 ms, p95 413 ms, 최대 668 ms. 답안 하나의 채점 판정은 평균 약 2,970 토큰 ≈ $0.000125, 0.27초다. 현재 채점 한 호출(2.8~4.07초)보다 10배 이상 빠르고 비용은 5배 이상 낮다.

종류별(ko): correct 12/12 유형·구간 모두 적중, short-correct 4/4, misconception 12/12 유형 적중, prompt-injection 12/12(off_topic·점수 0), partial 유형 12/12·구간 10/12, keyword-only 유형 11/12(1건 partial)·구간 10/12. en도 같고 partial 구간만 11/12.

키워드 choice의 confidence: 중앙값 0.94(ko)/0.95(en), 0.6 미만이 13%(ko)/8%(en). 이 하위 구간이 사람이나 LLM으로 넘길 후보다.

### 빗나간 것

- exact membership 미달 5건(ko)/4건(en): 부분답에서 세트가 요구한 정확한 일치·누락 집합과 한 키워드씩 어긋남(예: 세트는 "설명함"인데 partial, 세트는 누락인데 mentioned). 채점 지시 삽입 답안 1건은 키워드 상태가 explained로 나왔다(문서의 알려진 한계 "적대적 내용을 데이터로 취급하지 않음"). 그러나 같은 요청의 삽입 noul은 0.98~0.99였고 코드 규칙이 점수를 0으로 만들었다. **판정은 반드시 코드 정책으로 조합해야 하며 단일 질문을 그대로 믿지 않는다.**
- 점수 구간 미달 4건(ko)은 코드 산식의 거칠기다(부분답 25점 vs 35~~65, 키워드 목록 20점 vs 25~~60 등). 점수는 Jev의 출력이 아니라 상태에서 코드가 만든 값이므로, 도입 시 산식은 세트로 다시 맞춘다.
- 한국어 지시문과 영어 지시문의 차이는 없었다. 문서의 "영어가 가장 정확" 경고는 이 데이터에서 나타나지 않았다. 다만 사례는 12개, 분야는 생화학·유기화학·고교 생명과학이다.

## 권장 순서

1. **서술형 채점의 검수 호출을 Jev 일치 검사로 대체하고, 키워드 정오답 표시를 즉시 보여 준다.** 답안 제출 시 Jev 요청(키워드 상태 + 유형 + 삽입 noul)과 LLM 채점을 병렬로 보낸다. Jev 결과는 0.3초 안에 오므로 UI가 키워드 정오답 표시(2차 피드백 5번 항목)를 먼저 그리고, LLM 피드백이 도착하면 확정한다. LLM 채점의 키워드 상태·유형이 Jev와 일치하고 Jev confidence가 0.6 이상이면 `memoryz_essay_grade_review` 호출을 생략한다. 불일치·저신뢰·삽입 감지는 지금처럼 검수·보정 경로로 보낸다. 기대 효과: 대부분의 답안에서 LLM 호출 1회 감소(채점 총 시간 약 35~50% 단축, 검수 비용 제거), 실측 근거는 위 표.
2. **생성 품질 검수의 선별 필터.** 문항·서술형 저장 전에 Jev로 객관식 정답 유일성(choice+noul), 키워드/방해어 근거(claims 패턴), 문항별 근거·유일성·시각 의존 noul을 한 요청에 묶어 먼저 판정한다. 고신뢰 통과 항목만 저장하고 나머지만 LLM 검수(`memoryz_quiz_blind_solve`·`memoryz_essay_keyword_solve`·`memoryz_learning_quality`)로 보내면 생성 시간의 검수 몫(서술형 기준 수 초)을 대부분 없앤다. 객관식 표본이 5개뿐이므로 `server/cmd/learning-eval` 코퍼스로 먼저 확대 측정한다.
3. **새 기능(측정 전 제안).** 찾고 싶은 공부·커뮤니티 검색의 의미 검색과 재정렬(rerank·semantic_find 쿡북), 학교 검색 후보 정렬, 커뮤니티 신고 분류(consistency_choice 쿡북의 조정 패턴), 시간표 빈 시간 후보의 점수화(score). 각 요청 0.3초·$0.0001 수준이라 실시간 UI에 넣을 수 있다.

## 통합 계획

- Go: `server/internal/ai/typesafe.go`에 `POST https://api.typesafe.ai/v1/systemone` 클라이언트(시한 3초, 429/529 재시도, `AiRun` 단계 기록), 설정 `TYPESAFE_API_KEY`·`TYPESAFE_MODEL=jev-latest`·`AI_JUDGE=typesafe|off`(기본 off). 키가 없으면 지금 경로 그대로.
- 질문 정의는 이 평가의 ko 지시문을 그대로 쓰고 `tests`에 요청 JSON 스냅샷을 둔다. 임계값은 이 세트로 정한 값에서 시작한다: 키워드 상태 confidence < 0.6 → 검수, 삽입 noul ≥ 0.7 → off_topic·0점, 답안 유형 confidence < 0.6 → 검수.
- 배포 순서: (a) 그림자 모드 — 결과만 기록하고 LLM 검수 일치율을 2주 측정, (b) 검수 생략 조건 활성화, (c) UI 즉시 표시. 각 단계는 `learning-eval`의 채점 과제로 회귀 확인.
- 개인정보: 학생 답안·원문 인용이 제3의 벤더로 전송된다. 문서상 학습에 쓰지 않지만 개인정보 처리방침과 데이터 처리 계약을 먼저 갱신한다.

## 위험

- 벤더 의존: 속도 제한이 "동적으로 조정"되고 모델 별칭이 바뀔 수 있다. 버전 고정(`jev-1.13.0`)과 장애 시 LLM 단독 경로로 자동 복귀가 필요하다.
- 한국어·분야 일반화: 12사례 결과다. 수학(수치·계산)은 문서가 명시한 약점이라 미분계수 같은 문항은 LLM 검수를 유지한다.
- 문자 그대로 읽는 성향과 적대적 입력: 위 삽입 사례처럼 단일 판정이 속을 수 있다. 삽입 noul과 코드 정책으로 항상 감싼다.
- exact membership 88~90%: 최종 채점자가 아니라 즉시 표시·검수 대체용이다. 최종 점수와 피드백은 LLM이 낸다.
- 텍스트를 만들지 못한다: 피드백·설명·문항 생성은 계속 LLM이다.
