## 구현 계약

- 학기 반복: 일반 일정은 시작일~종료일과 주간 요일, 4주/16주 빠른 설정. 최대183일·200개. 학교 시간에도16주 추가.
- 반복 충돌: 새 일정·이미 등록·겹침을 날짜별로 구분. 일반 일정에서 충돌 날짜 제외는 사용자가 직접 선택해야 한다. 학교 일정은 기존 동작대로 겹치는 날 제외를 미리 안내한다.
- `POST /api/schedules/batch`: 사용자 행 잠금 안에서 모든 날짜를 검증하고 원자적으로 추가한다. 기존 내용이 정확히 같은 블록은 건너뛰며, 다른 일정과 충돌하면 아무것도 추가하지 않는다. 기존 고정/변동 일정을 수정하거나 삭제하지 않는다.
- 동일 요청을 다시 보내도 기존 동일 블록을 복제하지 않는다. 별도 요청 영수증 테이블은 없으므로 사용자가 나중에 삭제한 블록을 다시 요청하면 다시 등록된다. 이를 영구 요청 이력 보장으로 표현하지 않는다.
- 주간 배치: 할 일 최대8개(총 시간/회당 시간/요일/하루 한 번 옵션), 비교할 일정 최대3묶음×후보3개. 같은 묶음에서 후보 하나만 선택한다. 모든 고정·기존 변동 일정을 장애물로 존중한다.
- 세 가지 탐색 순서(고르게/앞쪽/뒤쪽)를 비교하고 부족 시간이 적은 순으로 최대9안을 보여 준다. 계산한 후보 내의 결과이며 전역 최적·불가능 증명으로 표현하지 않는다. 한 번에200개까지만 배치한다.
- 조건 기반 계산이며 AI라고 부르지 않는다. 기존 하루 AI 추천은 유지하되 저장은 같은 원자적 배치 API를 사용한다. 새 AI 호출이나 과금은 발생하지 않았다.
- 사용자가 명시적으로 선택한 미리보기만 등록한다. 부족 시간이 있으면 정확한 미배치 항목·분을 보여 주고 버튼은 ‘배치된 N개만 등록하기’라고 표시한다.

## 확인 범위

순수 TS16개(학기·경계·충돌·서로 다른 날·후보 조합·부족 시간·과거 시각·200개 제한), Go planner 검사, API 테스트 컴파일 확인. API의 격리 DB 통합 테스트와 실제 브라우저 조작은 상위 통합 작업에서 실행한다. 이 문서만으로 브라우저/운영 성공을 주장하지 않는다.
