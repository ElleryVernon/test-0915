# 대학 교재 학습 품질 평가

이 검증은 사용자가 제공한 Lehninger 28개 장과 McMurry 31개 파일을 대상으로 한다. PDF 원본과 전체 추출문, 실모델 응답은 로컬 ignored `.unlazy/university-learning/`에 보관한다. 운영 DB·계정·배포는 변경하지 않는다.

## 독립된 네 단계

1. **추출**: 실제 업로드와 같은 PDFium으로 전체 59개 파일을 읽고 SHA-256, 독립 `pdfinfo` 페이지 수, 본문/이미지 앵커를 확인한다. 원본 페이지를 렌더링해 두 단 순서와 수식 손실도 대조한다.
2. **정답 기준**: 출제 모델 결과를 보지 않은 별도 검토에서 8개 주제·40개 답안을 작성했다. 개발 4개, 미사용 검증 4개, 각 교재/분할을 균등 구성했다. 정답·부분답·핵심 오개념·키워드 나열·프롬프트 주입을 포함한다. 원문 발췌와 점수 구간은 해시로 동결했다.
3. **생성/피드백**: 제품의 실제 `GenerateItemsForTopic`, `GradeWithAI`를 호출한다. 문법·인용 검증과 과학적 타당성 평가를 구분한다. 생성 결과는 정답/근거/유일성/자료 수준/학습적 설명을 모두 충족해야 통과한다. 점수는 독립 구간·키워드 의미 분류를 확인하고 피드백의 사실성·답안별 구체성·다음 행동을 별도로 검토한다.
4. **제품 통합**: 별도 로컬 QA 계정에서 실제 PDF 업로드, 전체 본문 저장, 문제 생성, 답안 제출, 원문 확인을 검사한다. API·모델 평가가 통과해도 브라우저에서 사용 가능한 결과가 나타나지 않으면 완료가 아니다.

## 평가가 실패하는 조건

- 정답 키와 해설 불일치, 둘 이상의 정답, 출처 밖 핵심 주장, 필요한 그림/반응식 부재는 치명 오류다. 평균 점수로 상쇄하지 않는다.
- 출제 품질 점수 0~4 중 대학 수준과 설명 유용성 각각 3 이상이 필요하다. 단순 계산 예 복사·자기 반복·독립 질문 과밀을 구분한다.
- 플래시카드의 정확한 조건 비교에는 출처 밖 기전을 강제하지 않는다. 질문이 요구한 답을 정확히 충족해야 한다. 이 기준을 바꿀 경우 이전 버전의 **저장된 출력에도 같은 평가기**를 적용하며, 생성물을 다시 뽑아 기존 실패를 지우지 않는다.
- 모델 평가기는 생성 호출과 분리되어 있지만 같은 모델 계열이다. 독립 전문가 검증을 대체하지 않는다. 동결 정답과 원본 수동 대조를 함께 사용한다.
- 429·타임아웃·인용 거절·품질 탈락을 분리한다. 거절은 위험 문항을 저장하지 않았다는 증거이며 유용한 생성에 성공했다는 의미는 아니다.

## 적용한 보호 장치

- 고교로 고정하던 지시를 자료 수준에 맞게 변경했다. 대학 자료의 조건·예외·속도/평형·겉보기/고유값을 보존한다.
- 모델이 과학 기호를 다시 써서 인용을 변조하는 대신 **원문 구간 ID**를 선택한다. 서버가 연속된 구간을 직접 연결한다. 없는 ID, 역순/비연속, 중복, 길이 초과는 거절한다. 출처를 요약하거나 수식을 자동 복원하지 않는다.
- 생성 후보마다 별도 의미 검수를 수행한다. 실패하면 이유를 주고 한 번 다시 생성하며, 새 후보도 검수를 거쳐야 저장한다. 카드는 최대 생성 2회+검수 2회로 제한한다. 객관식은 정답·해설을 가린 독립 풀이를, 서술형은 정답 개수·키를 숨긴 선택지별 검토를 각 후보에 추가한다(각 최대 6회 호출). 모든 호출은 하나의 제품 제한 시간을 공유한다.
- 채점은 개념 60·논리 25·완결성 15를 나눠 평가하고 서버가 합산한다. 핵심 모순 25점, 나열형 20점, 답 대신 채점 지시만 쓴 경우 0점으로 제한한다. 키워드 ID를 사용해 원래 표기를 유지한다.
- 두 단 본문을 같은 행으로 합치던 PDF 추출을 수정했다. 업로드·저장·생성 본문 제한은 공통 500,000자로 관리하며 초과분을 조용히 자르지 않는다.
- `AI_QUALITY_REVIEW`는 기본 true다. 명시적 false는 이전 경로로 되돌리는 운영 설정이며 품질 검증 완료를 뜻하지 않는다.
- `OPENROUTER_QUALITY_MODEL`로 출제 모델과 별도의 검수 모델을 지정할 수 있다. 기본은 비어 있으며 출제 모델을 사용한다. 검수도 같은 동시 실행 한도와 HTTP 클라이언트를 사용하고 실제 사용 모델·시간·비용을 호출별로 남긴다. 단지 강한 모델이라는 이유로 전역 기본값을 바꾸지는 않는다.
- 생성 2.7.0은 실제로 존재하는 인용 ID만 선택지로 제공한다. 서술형은 완성된 답안 안의 `[[핵심 표현]]` 네 곳을 서버가 분리하므로 조사·띄어쓰기가 끊기지 않는다. 정답을 숨긴 독립 키워드 검토에 더해 의미가 같은 키워드의 중복, 비율 방향, 실험 내/실험 간 조건, 유리한 조건과 필요조건의 혼동을 검수한다.
- 채점 2.7.0은 각 개념을 `explained / partial / mentioned / contradicted / missing`으로 나누고 학생 답안의 실제 연속 구절을 요구한다. 서버가 원문·모범답안에서 가져온 가짜 답안 근거, 중복·누락 인덱스, 만점과 미충족 개념의 모순을 거절한다. `explained`만 충분히 설명한 개념으로 집계하며 `Km 증가`처럼 짧아도 정확한 명제는 인정한다. `partial`은 일부를 맞힌 답으로서 양수 부분점수와 맞은 부분의 확인이 필요하지만 전체 설명 완료로 세지는 않는다. 기존 문항의 중복·동의 표현에 동일한 답안 근거를 적용할 수 있으며 같은 사실을 다시 쓰라고 요구하지 않는다. 불완전한 답에는 교정과 구체적인 다음 행동을, 완전한 정답에는 오류를 지어내지 않은 완료 피드백을 요구한다. 만점 피드백은 같은 칭찬을 여러 번 반복하지 않고 완료 확인과 선택적 추가 연습만 반환한다. 형식·근거 검증 실패는 남은 시간 안에서 최대 한 번 보정하며 429/결제/업스트림 오류는 즉시 반환한다.
- 서술형 생성 2.8.0은 섞인 8개 선택지를 각각 원문 근거·판정·이유·가능한 반례로 검토한다. 참이 될 수 있는 방해어, 숨은 조건, 누락된 판단 근거, 중복·누락된 검토를 거절한다. 인용은 연속된 원문이고 공백 정리만 허용한다. 독립 검토 모델도 오류를 낼 수 있으므로 인용 존재를 과학적 타당성의 자동 증명으로 부르지 않는다.
- 현재 평가기의 제품 제한 시간은 실제 HTTP와 같은 180초다. 예전 동결 비교의 300초 한도는 소급 변경하지 않으며 실제 서비스 성공률로 부르지 않는다. 실패한 HTTP 호출도 상태·시간·비용 미확인을 남긴다. 청구 정보가 없는 실패의 비용을 0원으로 단정하지 않는다.

## 재현 명령

```sh
node scripts/university-corpus.mjs --verify
node evals/university/validate.mjs --self-test
cd server && go test ./internal/ai ./internal/pdfx ./internal/learning ./internal/config ./internal/planner ./internal/api ./cmd/learning-eval
```

실모델 호출은 `.env`의 기존 공급자 설정을 사용하며 새 결과 디렉터리만 허용한다. 모델 비용이 발생한다. 위 로컬 검사와 달리 아래 명령은 외부 모델에 교재 발췌를 전송한다.

```sh
node scripts/learning-eval.mjs --allow-live --split dev --jobs 1 --count 2 --out ../.unlazy/university-learning/dev-new
node scripts/learning-eval.mjs --allow-live --split holdout --jobs 1 --count 2 --out ../.unlazy/university-learning/holdout-new
node scripts/learning-eval.mjs --allow-live --split all --jobs 1 --tasks quiz,essay,cards --extraction-dir ../.unlazy/university-learning/extraction/current --out ../.unlazy/university-learning/extracted-new
```

`--review-results /absolute/report.json`은 동일 사례 해시의 저장된 결과를 재평가한다. `--ids`와 `--answers`로 실패한 사례를 명시적으로 재현할 수 있다. 실패를 고친 뒤에는 전체 개발 세트와 새 검증 세트를 통과해야 한다. 검증 세트의 출력을 보고 수정했다면 그것은 이후 회귀 세트이며 새 미사용 사례가 필요하다.

`--judge-model`은 제품 검수와 별개의 오프라인 평가 모델을 지정한다. 저장된 결과의 재평가에서는 원래 제품 지연 시간을 유지하고 새 평가 호출만 사용량에 기록한다. 새 생성 비용·속도를 측정한 것이 아니므로 비용 비교에는 원래 보고서를 사용한다. 이 계정의 동시 실행 2개 평가에서 429가 다수 발생했다. `final-all`의 7/64는 인프라 실패가 섞인 결과이며 품질 통과율로 사용하지 않는다. 이후 실행은 `--jobs 1`로 순차 수행한다.

## high와 xhigh 비교

```sh
node scripts/learning-reasoning-compare.mjs --allow-live --out .unlazy/university-learning/effort-new
```

동일 바이너리·모델·자료·스키마·16,384 출력 토큰 상한을 고정한다. 두 교재의 2개 개발 주제에 대해 객관식/서술형/카드 각 1개와 정답/오개념/나열 답안을 각 추론 수준에서 3회 실행한다(수준별 36과제). 순서는 high→xhigh / xhigh→high / high→xhigh로 교차한다. 오프라인 평가 모델은 high로 고정한다. 제품의 생성/검수/재생성 시간을 포함하고 평가기 시간은 별도로 기록한다. 비용과 추론 토큰, 실제 공급자도 기록한다. 표본이 작아 통계적 우월성이나 모든 교재에 대한 일반화를 주장하지 않는다.

참고: [OpenRouter reasoning](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens), [모델의 지원 추론 수준](https://developers.openai.com/api/docs/models/gpt-5.6-luna).

비교 바이너리는 실험 시작에 동결한다. 실험 중 추가한 개선은 이 비교 수치에 소급 반영하지 않으며, 새 버전은 별도 회귀/검증 결과로 기록한다.

작업별 평균 시간: 객관식 7.83→11.60초, 서술형 16.69→23.87초, 카드 7.91→7.48초, 채점 3.24→4.07초. 카드의 역전은 high 한 번의 지연 영향이 크며 중앙값은 6.54→7.40초였다. 생성은 한 번에 1개를 요청한 실험이므로 앱의 3~10개 생성 시간으로 해석하면 안 된다.

결론: 이 표본에서 xhigh의 일관된 품질 이득은 관찰되지 않았다. 기본 high를 유지한다. 특히 조건 누락, 질문에 답하지 못하는 모범답안, 키워드 분류 오류는 추론 수준만 높여 해결되지 않았다. 이후 추가한 독립 객관식 풀이·출처에 맞는 서술형 설계·부분점수 보정은 별도 버전으로 검증한다. 전체 원자료는 `.unlazy/university-learning/reasoning-comparison/comparison.json` 및 여섯 회차 보고서에 남겼다.

독립 에이전트가 자동 실패 12건을 다시 읽었다. high의 5건은 생성 실패 2·실제 품질 문제 3, xhigh의 7건은 생성 실패 1·실제 품질 문제 3·평가기의 과도한 요구/오독 3으로 분류했다. 성공한 60건까지 독립 재검토한 것은 아니므로 이 분류로 수정 통과율을 만들지 않았다. 원래 31/36 대 29/36만으로 **xhigh가 더 나쁘다고 단정할 수 없다**. 관측된 속도·비용 증가와 불확실한 품질 차이를 구분한다. 근거는 `gold/reasoning-failures-review.md`와 항목별 해시를 가진 JSON이다.

## 실제 제품 확인과 발견된 한계

독립된 로컬 QA 계정에 48쪽/188,662자와 118쪽/352,658자 PDF를 업로드했다. 본문 길이와 메타데이터가 저장되었고, 48쪽 자료에서 서술형 3개 생성은 25.451초였다(생성 2.6.0, Luna). 실제 화면에서 핵심 원리를 뒤집은 답안은 9점, 정확히 바꾸어 쓴 답안은 100점으로 채점됐으며 원본 PDF의 인용 위치인 20쪽까지 열었다. 마지막 수정 답안도 100점으로 확인했다. 이미지·API·원자료는 로컬 `.unlazy/university-learning/`에 보관한다.

그러나 이 3개 문제를 독립 검토하니 의미가 겹치는 키워드, 반최대 속도를 잘못 표현한 답, 곡선 비교에서의 조건 누락이 발견됐다. 흐름이 동작한 사실과 내용 품질을 분리한다. 또 실제 추출문 평가에서 반환된 10개 중 2개에 모호한 객관식 오답과 키워드 의미 중복이 남았다. 반환되지 않은 2개는 품질/인용 검증에서 저장을 거절한 경우다. 이 발견이 생성 2.7.0의 추가 검수와 별도 모델 실험의 근거이며, 이전 결과를 성공으로 다시 쓰지 않는다.

긴 원문 인용은 기본 여섯 줄 미리보기와 ‘전체 근거 보기’로 제공하고 원본 연결을 유지한다. 정확한 답안에는 ‘잘 설명했어요’를 보여 불필요한 수정 요구를 피한다. 브라우저에서 미리보기/펼치기와 원본 PDF 연결을 확인했다.

## GLM 5.3 Flash / Baseten FP8 비교

OpenRouter 공개 endpoints API에서 `z-ai/glm-5.3-flash`의 `baseten/fp8` 경로를 확인했다. 2026-09-17 조회값에서 FP8·JSON structured output은 지원하지만 강제 `tool_choice:function`은 지원하지 않았다. `OPENROUTER_STRUCTURED_MODE=json_schema`를 명시적으로 선택하는 경로를 추가했으며, 유료 실패 뒤 다른 전송 방식이나 공급자로 자동 재시도하지 않는다. 기존 기본 경로는 `function`이다.

```sh
node scripts/learning-model-compare.mjs --allow-live --out .unlazy/university-learning/model-new
# 공급자 제한으로 중단된 경우에만, 같은 동결 바이너리/자료로 재개:
node scripts/learning-model-compare.mjs --allow-live --out .unlazy/university-learning/model-new --resume
```

Luna(OpenAI fast)와 GLM(Baseten FP8)은 최신 동일 바이너리·JSON 스키마·high 요청·16,384 출력 토큰 상한을 사용한다. 두 주제의 출제 3종과 정답/오개념/키워드나열 채점으로 회차당 12과제를 구성하고, 모델당 3회(36과제), 순서를 교차한다. 각 모델이 제품 내 검수도 담당하며, **오프라인 평가기는 양쪽 모두 Luna/high/OpenAI fast로 고정**한다. 추론 수준의 이름이 같다고 모델 간 실제 연산량까지 같다는 의미는 아니다. 앞선 high/xhigh 실험은 구버전이므로 새 표의 Luna 행과 수치를 직접 섞지 않는다.

실제 모델·공급자 이름을 호출별로 검증하고 `baseten/fp8` 외 경로로 우회하지 않는다. API에 저장된 providerOrder와 공개 endpoint의 quantization=fp8, 응답의 provider=BaseTen을 함께 기록한다. 429·결제 한도·타임아웃이면 즉시 중단하고 부분 결과를 남긴다. 미실행 과제를 실패율의 분모에 넣거나 완료로 표시하지 않는다. 재개할 때도 중단된 시도의 데이터는 보존한다.

연결 확인에서 최초 Baseten 429는 `upstream_provider_shared_pool` 제한이었다. 간격을 둔 다음 실응답은 BaseTen으로 확인되었고, 정답 채점 100점·제품 12.896초·$0.0006744였다. 이 1건은 본 비교 통계에 포함하지 않는다. 피드백에 ‘倒数’가 섞인 한국어 품질 문제는 사실성 점수와 별도로 기록한다.

참고: [OpenRouter 공급자 고정과 quantization](https://openrouter.ai/docs/guides/routing/provider-selection), [GLM endpoints API](https://openrouter.ai/api/v1/models/z-ai/glm-5.3-flash/endpoints).

### 최종 요청: Together 경로

사용자가 Baseten에서 Modal FP8, 이어 Together로 경로를 변경했다. Baseten 두 시도는 429로 중단되었으며 품질 비교의 분모로 사용하지 않는다. Modal은 공개 설정만 확인하고 유료 비교를 실행하지 않았다. Together의 공개 tag는 `together`, quantization은 `unknown`이다. 따라서 **Together 결과를 FP8 결과라고 표기하지 않는다**. 초기 연결 확인은 실제 provider `Together`, 정답 100점, 제품 5.648초, $0.00061425였으며 반복 비교에서 제외한다.

```sh
node scripts/learning-model-compare.mjs --allow-live --glm-provider together --out .unlazy/university-learning/together-new
```

공급자는 새 실험의 manifest에 고정한다. `--resume`에 다른 공급자를 전달하면 호출 전에 거절하여 중간에 공급자가 섞이지 않게 한다. JSON schema·요청 effort high·출력 한도·오프라인 평가기는 기존 실험 조건과 같지만, 공급자가 바뀐 실험은 별도 디렉터리에 기록한다.

### 이후 결정: Luna/high 유지, 추가 GLM 비교 종료

사용자가 Luna로 돌아가 채점 개선을 이어가라고 명시했다. 제품 설정은 계속 `openai/gpt-5.6-luna` / `high`이며 GLM은 오프라인 평가에서만 사용했다. 추가 GLM 반복은 중단했다. `glm-together-staged/round-1-glm-product-attempt-1/report.json`에는 종료 직전 완료한 12개 제품 과제와 26회 호출이 남아 있다. 그중 한 서술형 생성은 품질 검수에서 거절됐고, 한 나열형 답안 피드백에는 다음 학습 행동이 부족했다. 이 10/12는 **별도 오프라인 심사를 받지 않은 제품·고정 규칙 결과**이며 완결된 3회 교차 비교나 독립 품질 통과율이 아니다. 나머지 회차를 실행한 것처럼 집계하지 않는다.

기존 비교 원자료와 실패는 보존한다. 이후 채점 검증에는 원래 개발 4주제와 새 `grading-holdout-v2.json`의 헤모글로빈 협동 결합·Diels–Alder 2주제를 쓴다. 새 자료는 모델 출력 전에 동결한 12답안으로, 짧은 정답과 나열형을 구별하고 모든 개념의 충족/미충족을 명시한다. 기존 미사용 4주제는 이미 결과를 보고 수정에 사용했으므로 더 이상 새로운 holdout으로 부르지 않는다.

### 자동 평가의 한계와 추가 검증

생성 2.7.0/채점 2.4.0의 별도 미사용 검증 4주제·32과제는 자동 29/32였다. 429 없이 완료했지만, 모호한 메소 화합물 방해어, DNA 교정 피드백의 PPi 표현, 전부 틀렸다는 과도한 피드백 지적이 남았다. 상세 원자료는 `holdout-2.7-final/report.json`에 있다. 전체 제품 품질 게이트는 아직 통과하지 않았다.

Luna 파일럿 자동 12/12도 독립 재검토에서는 조건 표현의 정밀성, SN2 가능성과 E2 우세를 반대 관계로 취급한 방해어, 단어 나열 답안의 전부 matched 표시 문제를 확인했다. 자동 점수와 독립 감사는 따로 보존한다(`gold/model-pilot-review.md`). 이는 모델 우열을 판정할 때 자동 통과율만 사용하지 않는 이유다.

더 강한 검수 모델의 제한적 실험도 남겼다. Luna 출제/Astra 검수는 서술형 2과제 중 1개, Terra 출제/Astra 검수는 2개를 자동 통과했지만 충분한 표본이 아니다. 확대 실행은 고비용 요청의 HTTP 402로 중단했다. 계정의 소액 잔액으로 Luna/GLM 호출은 계속 가능했으므로 전체 API가 불가능했다고 표현하지 않는다. 결제·충전이나 기본 모델의 운영 변경은 하지 않았다.


### 채점 2.5–2.7 추가 개선 경로

채점 2.5의 개발20·새 v2검증12는 고정 규칙상31/32였다. 헤모글로빈 partial66점은 동결 상한65보다1점 높은 결과로 그대로 보존한다. 독립32개 전수 검토에서는 치명적 과학 오류는 발견하지 못했지만, 나열 답안 안의 실제 부분 정답을0점으로 처리한2건을 추가로 발견했다. 고정 규칙 통과와 의미 검수가 같은 결과가 아님을 보여 준다.

오프라인 judge2.2의 개발 결과는16/20이다. 실패4건을 다시 읽은 결과3건은 짧은 명제에 과도한 형식을 요구하거나 matched의 의미를 오독했고,1건은 상세 이유가 없어 판정 원인을 확인할 수 없었다. 원래16/20을 덮어쓰거나 모두 제품 결함으로 세지 않는다. 평가기2.2.1부터 이유가 비어도 실패한 판단 항목(정확성·구체성·다음 행동·개념 판정)을 보존한다. 이는 평가기의 판단을 추적하기 위한 변경이며 평가기의 과학적 신뢰도가 입증되었다는 뜻이 아니다.

채점2.6은 부분 정답 상태를 도입했고 기존 개발20개를 고정 규칙상통과했다. 실제 앱에서는 중복된 ‘정상 Vmax / Vmax 불변’ 중 하나만 인정하면서 같은 뜻을 다시 쓰라고 요구하는 문제가 발견되었다. 채점2.7은 기존 문제의 이런 동의·중복 표기를 독립된 추가 요구사항으로 취급하지 않도록 보강했다. 만점 피드백의 반복도 제거했다.

v2의 결과를 보고 수정했으므로 v2는 이제 회귀 사례다. 새 `grading-holdout-v3.json`은 Lehninger 펩타이드 결합의1주제6답안을 출력 열람 전에 동결했다. 나열 형식 안의 실제 두 명제에는 양수 부분점수와 개념 인정을 요구한다. 기존 gold의 점수 구간과 실패는 변경하지 않는다. 최종 버전의 원자료·독립 감사·실제 제품 확인은 아래 실행 결과로 별도 기록한다.


### Luna 복귀 후 2.8 실험과 회귀

서비스는 계속 Luna/high이며 GLM 추가 비교는 사용자 요청대로 종료했다. 채점 2.8.0은 답안의 원문 구절·개념 판정·점수·피드백을 별도 호출에서 검수하고 한 번만 보정한다. 전체 제한 시간180초, 최대4호출이다. 재검수도 확률적이며 자체로 정확성의 증명이 아니다.

같은 동결58답안에서 2.7.1은 고정 규칙52/58·58호출·평균5.74초·중앙값4.75초·$0.1936, 2.8.0은46/58·139호출·평균10.78초·중앙값8.37초·$0.4043이었다. 별도 오프라인 모델 judge 없이 동결 점수/개념 기준과 독립 전수 감사로 확인했다. 2.8.0의12실패에는 채점 거절5건이 포함된다. 나열형 점수상한을 잘못 적용한 옛 gold와의 충돌, 점수 경계, 실제 과대점수와 개념 오류를 분리한다. 따라서 검수 추가를 일괄적인 품질 개선으로 보고하지 않는다. 원본 결과는 덮어쓰지 않는다.

실제 QA 화면에서도 기존2.6 생성 문항의 중복 키워드인 정상 Vmax/Vmax 불변 중 하나만 인정한24점 결과가 남았고, 동등한 설명에 문항의 조건을 다시 쓰도록 요구하며87점을 준 사례를 확인했다. 2.8.1은 문항의 주어진 조건을 답안에 적용하고, 조건의 부정/변경이 없으면 문자 그대로의 재서술을 요구하지 않도록 수정했다. 첫 실제 재검증은 채점 근거 거절로 끝났으며 해결로 집계하지 않는다. 답안은 화면에 남았다.

그 이후 처음 채점한 독립 v4(글리코겐 가지 제거)의6답안은2.8.1 고정 기준6/6이었다. 정답·짧은 정답100, 부분83, 오개념21, 짧은 명제 혼합42, 지시 주입0점이다. 직접 산물·정지 잔기 수는 짧게 써도 인정하고, 전이의 일부만 맞힌 답에는 부분점수와 나머지 작용 설명을 제시했다. v4는 출력 확인 이전에 원본2쪽 렌더/연속3744자/24개 의미 판정을 동결했다. 이6개는 다른 버전의58개와 합쳐 같은 모델버전의 통과율로 계산하지 않는다.

### 서술형 생성 2.9 후속 검증

2.8 생성의11시도에서9문항이 반환되고2건이 거절됐다. 반환9개를 독립 전수검토한 결과 허용4·수정필요5였다. 치환/제거의 우세와 가능성 혼동, 핵심결과 키워드 누락, 에너지의 같은 오개념을 반복한 방해어, 메소형 대상 모호성, 한국어 명사구 접붙임을 기록했다. 인용이 모두 원문과 일치해도 내용 타당성이 보장되지 않는 사례다.

`--capture-responses`는 오프라인 채점 진단을 명시적으로 켤 때만 사용한다. 기본은 꺼져 있고 실제 제품 요청이나 로그에는 원문 응답을 남기지 않는다. 켠 평가 결과에는 채점·별도 검수의 디코딩된 JSON만 과제당 최대4개 보관한다. # GPT-5.6 공식 가이드 적용 (2026-09-17)

[GPT-5.6 공식 가이드](https://developers.openai.com/api/docs/guides/latest-model?model=gpt-5.6)의 짧고 중복 없는 프롬프트, 실측 오류를 교정하는 예시 유지, 동일 과제로 성능 확인 원칙을 적용한다. 모델은 `openai/gpt-5.6-luna`, reasoning은 `high`를 유지한다. 가이드의 `gpt-5.6` 별칭은 Sol이므로 Luna 대체 이름으로 쓰지 않는다.

실제 코드에서 발견한 충돌은 두 가지다. 검수 활성 경로가 먼저 `modelAnswer`와 `keywords`, 원문 `citation`을 만들라고 지시한 뒤, 다시 `annotatedAnswer`와 `citationIds`만 출력하라고 덧붙였다. essay 2.10은 활성 스키마와 일치하는 단일 프롬프트를 사용하고 고정 지시 뒤에 주제·재시도 진단·원문 데이터를 둔다. 일반 생성의 기존 계약은 유지한다. 실제 HTTP 요청의 프롬프트와 스키마를 함께 검사하는 회귀 테스트로 충돌 재발을 확인한다.

grade 2.9는 중복 규칙을 통합하고 만점을 충족하는 60/25/15 기준을 명시했다. 2.9 첫 측정에서 짧은 결과를 원인 설명 부족과 혼동한 사례가 다시 나와, 2.9.1에는 개별 결과와 전체 인과를 분리하는 예시를 유지했다. 기존 점수·원문 근거·의미 검수·최대 재시도 수는 완화하지 않는다. 실험별 바이너리와 최초 실패를 보존하며, 적은 토큰만으로 품질 향상을 주장하지 않는다.

공식 Responses API의 persisted reasoning, pro mode, explicit caching은 현재 OpenRouter Chat Completions 경로에 무조건 추가하지 않았다. 이번 변경은 모델·엔드포인트 교체가 아닌 현재 Luna 워크로드의 프롬프트 정리다. 고강도 추론은 기존 high/xhigh 실측으로 판단하며 공식 문서의 일반 성능 수치를 이 서비스의 효과로 대체하지 않는다.

### 채점 거절의 실제 원인과 수정

opt-in 원응답에서 두 가지 구조적 실패를 확인했다. grade 2.9.1은 완전한 정답에 60/25/15와 4개 explained를 주고 성공 설명을 strengths에 썼지만 completion이 비어 있어 재채점됐다. 재채점은 정확한 바꾸어 쓰기를 partial로 바꾸었다. 2.9.2는 이미 검증된 100점·오류 없음 조건에서 strengths의 기존 문장을 그대로 표시할 수 있게 한다. 점수를 올리거나 근거를 만들지 않고 원응답도 변경하지 않는다. 점수 부족·근거 누락·아무 피드백도 없는 응답은 계속 거절한다.

2.9.2의 용어 나열 평가에서는 검수기가 valid=true와 '기존 채점은 타당하다'는 issues 목록을 두 차례 함께 내놓았다. 서버가 이 모순을 무시해 통과시키지 않도록, 2.9.3은 스키마를 `review` 아래 두 분기로 나눈다. 통과 분기는 true+빈 목록만, 거절 분기는 false+1~6개 오류만 허용한다. strict decoding과 서버 재검증을 함께 유지한다. 실제 OpenAI 경유 Luna 호출에서 새 스키마 수용을 확인했다.
