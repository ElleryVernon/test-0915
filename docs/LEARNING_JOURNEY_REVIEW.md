# 학습 동작의 목적과 사용자 여정 재검토

2026-09-16 · 학생 체험 공간 · 로컬 Go API / Next 빌드

이 문서는 기존 버튼과 라우팅이 작동하는지를 넘어, 그 행동이 학습 목적과 맞는지 점검한다. 특정 회사 근무 경력이나 실제 사용자 연구에 근거한 평가는 아니다. 실제 앱 조작과 코드에서 관찰한 문제를 바탕으로 한 설계 판단이며, 사용자 연구를 통한 효과 검증과 구분한다.

## 판단 기준

1. 사용자가 이미 알고 있다면 불필요한 사전 동작 없이 시도할 수 있다.
2. 모른다고 해서 이유 없이 막히지 않는다. 도움을 보거나 다른 방식으로 계속할 수 있다.
3. 정답을 보기 전 스스로 떠올릴 기회를 준다.
4. 자신의 선택, 시스템 판단, 다음 행동을 구분한다.
5. 복귀·새로고침·중간 도움으로 작성한 내용과 진행이 사라지지 않는다.
6. 내용 이해를 평가해야 할 곳에서 클릭 순서나 글자 수를 이해의 대리 지표로 삼지 않는다.

## 발견한 모순과 수정

| 상황 | 모순·불편 | 수정 |
| --- | --- | --- |
| 서술형 시작 | 이미 아는 학생도 키워드/순서/힌트 3단계를 통과해야 글을 쓸 수 있음 | 빈 답안에서 바로 시작. 키워드와 예시 연습은 선택하는 도움 |
| 키워드 오답 | 모르는 학생에게 ‘관계없는 단어’라고만 하며 통과할 때까지 추측 요구 | 언제든 핵심 키워드와 실제 자료 근거를 보고 이어가기. 정답 개수 제한은 유지 |
| 순서 문제 | 단어 배열의 일치가 개념 이해를 대신 평가. 병렬 관계에도 단일 인과 사슬 강제 | ‘글의 순서’ 준비 도구로 변경. 유효한 키워드를 중복 없이 배치하면 어느 순서든 계속 가능. 의미 평가는 실제 작성 문장에 대해 서버가 수행 |
| 도식 힌트 | 방금 정답으로 맞힌 배열을 다시 힌트로 보여줌 | 자신이 정한 구성과 예시 답안을 선택해서 비교. 표현·순서가 달라도 핵심 관계를 설명하도록 안내 |
| 다시 풀기 | 이전 답안이 자동으로 노출되어 회상 기회를 없앰 | 일반 재진입은 빈 답안. 지난 답안은 펼쳐 보고 명시적으로 가져옴. 이미 쓰는 답안을 덮어쓰지 않음 |
| 답안 보완 | ‘한 문장 더 쓰기’가 내용 수정 대신 분량 늘리기를 유도 | ‘답안 고쳐 쓰기’. 답안과 코칭을 함께 보존. 같은 답안을 바꾸지 않고 재채점하지 않도록 이유 표시 |
| 오답노트의 서술형 보완 | 일반 재시도와 보완의 의도가 섞임 | ‘답안 보완하기’는 명시적 revise 진입으로 지난 답안을 가져옴. 진행 중인 최신 초안이 우선 |
| 객관식 결과 | 틀린 문제를 다시 풀려면 설정부터 재진입. 카드 만들기가 먼저 강하게 제안됨 | 틀린 문제만 바로 재시도. 카드 생성은 사용자가 선택한 문제만 대상이며 기본 일괄 선택 제거 |
| 객관식 해설 | 풀이 직후 학습과 무관한 과목 설정이 제시됨 | 해설 → 다음 문제/결과에 집중하도록 중간 설정 이동 제거 |
| 오답 다시 풀기 | 답안을 펼쳐야 ‘다시 풀기’에 도달하여 정답을 먼저 봄 | 정답을 펼치지 않고 바로 재시도. 해설 펼침 동작을 명시 |
| 카드 자기 평가 | ‘다시/보통/쉬움’이 정답을 본 뒤 이해 정도인지 회상 정도인지 불명확 | ‘정답을 보기 전에 얼마나 떠올렸나요’와 회상 기준 선택지. 선택 즉시 저장·다음 카드 전환 및 복습 예정 시점 안내 |
| 카드 새로고침 | 남은 카드 집합을 다시 계산하여 위치·평가·진행 손실 가능 | 세션 ID 목록, 위치, 뒤집힘, 평가, 시작/완료 시점과 완료 기록 여부를 방문에 보존 |
| 오래 걸리는 생성 | 닫기 안내는 거부하지만 히스토리 레이어는 이미 닫혀 동작 불일치 가능 | 화면 닫기를 허용하고 요청 보관 및 같은 자료에서 재확인 안내. 실제 생성된 개수로 완료 안내 |
| 늦게 도착한 응답 | 이전 화면의 상태 갱신이 현재 다른 화면 방문에 기록될 수 있음 | 상태를 원래 방문 ID에 귀속. 다른 화면에 늦은 결과를 섞지 않음 |
| 새로고침 뒤 이동 | 앱의 방문 기록과 Next의 페이지 복원이 같은 뒤로가기를 처리해 주소만 바뀌거나 닫기가 멈춤 | 공통 셸을 루트에 유지. 앱이 만든 방문의 popstate는 앱에서만 처리하고 그 외 방문은 브라우저에 맡김 |
| 기존 자동 검사 | ‘작성 전 단계 잠금’ 자체를 필수 동작으로 테스트함 | 바로 작성 가능·선택적 도움·다른 구성 허용·초안 우선·늦은 응답 분리를 검증하도록 조건 수정 |

## 이전 판정과의 관계

`docs/UX_JOURNEY_REVIEW.md`와 `.unlazy/ux-journey/GATES.md`는 이전 구현의 기록이다. 그중 서술형에 고정 순서를 정답으로 강제하던 G7/G8의 정책은 이번 설계로 대체한다. 과거의 ‘통과’를 현재의 학습 UX 전체 통과로 재사용하지 않는다. 현재 완료 조건은 `.unlazy/learning-purpose/GATES.md`에 기록한다.

## 실제 조작 기록

실제 브라우저에서 로컬 빌드와 기존 Go API를 사용했다. 서버의 AI 요청을 거쳤으나 운영 배포·모든 문항의 교육적 타당성·학습 효과나 사용자 만족도 검증을 뜻하지 않는다.

- **서술형 작성/도움:** 새 진입에서 빈 답안에 28자를 입력했다. 도움에서 방해 단어 4개를 선택한 뒤 핵심 키워드와 자료 근거를 열어 계속했다. `인슐린 → 혈당량 → 글리코젠 합성 → 포도당 흡수`처럼 기준 배열과 다른 글의 구성을 수용했다. 도움을 닫고 새로고침해도 작성한 답안이 남았다.
- **코칭/재작성:** 실제 제출은 15점, 보완한 다음 답안은 58점으로 응답했다. 다시 쓰기 후 새로고침해도 답안과 58점 코칭이 함께 남았고, 같은 답안 재제출은 이유를 표시하며 막았다. 내용을 보완한 83자 답안을 제출해 100점 결과를 확인했다. 점수 자체의 교육적 정확도를 검증한 것은 아니다.
- **오답 재시도:** 뉴런 문제의 해설을 펼치지 않고 재시도했다. 모름으로 0/1 결과를 낸 뒤 카드 생성이 기본 선택되지 않은 상태에서 틀린 문제 재시도를 눌렀다. 선택/결과가 초기화된 동일 문제에 정답을 제출해 1/1을 확인했다. 오답 목록이 8개에서 7개로 바뀌었다. 서술형 보완 진입은 지난 29점 답안을 명시적으로 가져왔고 뒤로가기는 서술형 탭을 유지했다.
- **카드:** 정답을 보기 전 회상 안내, 정답 뒤 네 가지 회상 평가를 390px 화면에서 확인했다. `떠올림`으로 평가한 뒤 2/10으로 진행했으며 새로고침해도 같은 두 번째 카드/진행률/앞면이 유지됐다. 닫으면 평가한 카드의 다음 복습 시점이 목록에 반영됐다.
- **생성 중 닫기/복구:** 세포 호흡 자료에서 3문제를 생성해 0→3개를 확인했다. 추가 3문제 생성 직후 창을 닫아 자료 상세로 돌아왔다. 다시 열었을 때 새 요청 버튼 대신 `문제 3개는 저장되었어요 / 만든 자료 확인하기`가 표시됐다. 확인 후 자료의 객관식 개수가 6개가 됐다. 총 두 번의 생성 요청을 시작했다.
- **라우팅 회귀:** 최신 빌드의 새 탭에서 학습→복습 1/9→새로고침→닫기→카드 목록→학습→검색까지 주소와 화면이 일치했다. 검색어 `세포`→자료→서술형 목록→새 문항→새로고침→목록→원래 자료→검색을 왕복했고 검색어가 복원됐다. 수정 전에는 이 경로에서 닫기가 멈추거나 검색 주소에서 학습 화면이 남는 문제가 재현됐다.

실제 모바일 OS의 키보드·제스처, 오프라인 재연결, 새 파일 업로드 및 모든 문항의 내용 검수는 이 기록의 완료 범위가 아니다. 자동 검사와 관찰한 화면 흐름을 위 표에서 구분했다.
