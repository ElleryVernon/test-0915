## 적용할 사용자 흐름

1. 만들기 진입 → 자료 선택. 과목 폴더/최근 자료에서 검색하고 최대 5개 선택. 선택 수와 제한은 하단에서 확인하며 선택 목록을 바로 열 수 있다.
2. 선택 확정 → 생성 설정. 개수가 첫 결정, 자료는 테두리 없는 파일 목록으로 확인. 변경하면 기존 자료와 개수를 유지한다. 다른 자료를 둘러봤더라도 취소하면 확정한 자료로 돌아간다.
3. 여러 자료일 때 선택적 주제 입력, 과목이 여러 개일 때만 저장 과목 선택. 설정에 없는 임의 유형/난이도/예상 시간을 만들어 약속하지 않는다.
4. 만들기 → 설정 폼 대신 실제 진행 상태. 시간에 맞춰 가짜 단계/퍼센트를 올리지 않는다. 닫을 수 있고 재진입 시 보관된 요청을 조회·폴링하며 새 생성 요청을 중복하지 않는다.
5. 성공 → 실제 저장된 개수와 근거 자료 확인. 서술형은 만든 문제 목록으로 바로 이동한다. 실패 시 자료와 개수를 보존하고 재시도를 명시적으로 제공한다.

같은 제한 높이를 사용하고 내부 목록만 스크롤한다. 표면은 흰색, 보조 선택은 회색, 선택된 수는 먹색, 실행은 기존 주황색. 상태/선택을 구분하려고 장식 테두리를 추가하지 않는다. 모든 단위는 기존 4px 간격 토큰과 공용 버튼·시트를 사용한다.

## 실제 실행 확인

- 서술형 목록의 만들기 버튼을 공용 하단 액션 영역에 고정했다. 720px 높이의 짧은 목록과 빈 목록 모두 하단이 720px였고, 998px 높이에서 7개 문제 목록을 끝까지 내려도 버튼 하단은 998px를 유지했다. 마지막 문제와 고정 영역 사이에는 약 12px의 여유가 남았다.
- 1280×720 브라우저에서 자료 선택과 설정 시트는 모두 높이 648px, 상단 48px, 열린 모달 1개였다. 설정 화면의 중복 설명과 자료 탐색 도구 줄을 줄여 짧은 화면에서도 목록 공간을 확보했다.
- 자료 2개 선택 → 문항 수 설정 → 자료 변경 → 선택 해제 → 변경 취소에서 확정 자료 2개와 문항 수 10개가 유지됐다. 본문이 짧은 자료는 선택 불가 이유를 표시한다.
- 격리된 로컬 QA 계정으로 자료 2개에서 서술형 3문제를 실제 생성했다. 생성 중 닫고 다시 열면 기존 요청을 자동 조회했고, DB에서 생성 요청 1개·완료 상태·새 문제 3개를 확인했다. 완료 버튼은 해당 3문제 목록으로 연결됐다.
- 문제은행과 플래시카드에서도 자료 선택부터 시작한다. 문제은행이 '기본 선택 없음'을 '보유 자료 없음'으로 오인하던 연결 오류를 함께 수정하고 회귀 검증을 추가했다.
- 작성 화면은 실제 문제 → 답안 입력 → 보조 도움 → 제출 순서로 정리했다. 60자 답안이 힌트·지난 답안·키워드 연습 전환과 새로고침 후 유지됐고, 입력 영역의 최소 높이는 220px였다.
- 타입 검사, 관련 학습·다중 자료·생성 복구·폴링 테스트, 프로덕션 빌드를 통과했다. 오류·중단·재시도 제한은 자동 테스트와 코드 검토로 확인했다. 실제 브라우저에서는 정상 생성·닫기·복구·완료를 검증했으며, 모바일 실기기 검증이나 운영 배포 결과로 해석하지 않는다.
