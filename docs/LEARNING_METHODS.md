# Memoryz 학습 방법론

## 채택: FSRS + 능동 회상 + 근거 피드백

FSRS는 답변 평가와 경과 시간을 바탕으로 카드의 난이도·기억 안정성·인출 가능성을 추적합니다. 고정 간격을 유지하는 기본 모드와 선택 가능한 적응형 모드를 병행해 기존 기획과 호환했습니다. `ts-fsrs`는 MIT 라이선스의 독립 구현이며 Anki 앱의 AGPL 코드를 복사하지 않았습니다.

- [Anki 공식 FSRS 설정과 목표 기억률](https://docs.ankiweb.net/deck-options#fsrs)
- [Anki 평가 버튼 의미](https://docs.ankiweb.net/studying.html#answer-buttons)
- [ts-fsrs 공식 문서](https://open-spaced-repetition.github.io/ts-fsrs/)
- [ts-fsrs 5.4.2](https://github.com/open-spaced-repetition/ts-fsrs/releases/tag/v5.4.2)

90%는 예정 시점에 기억할 확률의 목표입니다. 사용자 개인의 성적이나 실제 기억률을 보장하는 숫자가 아닙니다. 높은 목표는 더 많은 복습을 요구합니다. 초기에는 공개 기본 파라미터를 사용하고 충분한 기록 없는 개인 최적화는 수행하지 않습니다.

카드 앞면에서 먼저 답을 떠올린 뒤 뒤집는 능동 회상, 객관식 답변 뒤 원문 근거 확인, 서술형의 키워드·논리 순서·직접 쓰기를 한 흐름으로 연결했습니다. 기억이 나지 않으면 ‘다시’, 떠올렸지만 어려웠으면 ‘어려움’을 사용합니다. 자동 정답 노출이나 무조건 쉬움 평가는 학습 신호를 왜곡하므로 피합니다.

## 적용 선택

`src/lib/srs.ts`가 브라우저·서버의 단일 스케줄러입니다. 짧은 학습 단계는 1분·10분, 재학습 단계는 10분이고 반복 가능한 검증을 위해 fuzz를 끕니다. 온라인과 오프라인은 실제 평가 시각과 당시 목표 기억률을 저장합니다. UUID 리뷰로 재전송을 중복 계산하지 않습니다.

기존 ‘쉬움 두 번 → 암기완료’는 FSRS 모드에서 숙련 배지로 사용합니다. 기억이 영구적이라고 가정하지 않으며 기한이 되면 다시 복습합니다. 고정 방식의 암기완료는 기존 기획대로 정규 만기 목록에서 제외합니다.

## 비교와 보류

고정 Leitner식 상자는 이해하기 쉽고 현재 기획과 일치합니다. SM-2보다 상태가 풍부하고 TypeScript 공식 구현이 있는 FSRS를 추가 모드로 선택했습니다. 실제 사용자 기록에 대한 두 모델의 실험 비교나 학습 효과 향상 수치를 주장하지 않습니다.

지금은 핵심 카드 복습에 집중합니다. 일일 신규 카드 한도, 서로 비슷한 카드의 같은 날 노출 분산, 개인 파라미터 최적화는 실제 복습 로그와 사용량을 수집한 후 별도로 검증할 설계 항목입니다. 이 항목들은 현재 구현 기능으로 표시하지 않습니다.
