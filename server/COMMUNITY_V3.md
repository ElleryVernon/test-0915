# Community v3 backend

Migration 00008 adds community snapshots, action/reward/idempotency ledgers, profile visibility and card publication tables. Existing posts remain readable; deleting a post is soft deletion. PostgreSQL foreign keys clean dependent ledgers on account/source deletion. School/role/suspension/block checks apply before every post action.

Implemented endpoints (all `/api`):

- `GET/POST /posts`, `GET/PATCH/DELETE /posts/:id`. Feed filters: scope, mine, saved, commented, following, subjectId, unanswered, questionId (own question source). School comes from authenticated profile. Snapshot refs must belong to the publisher; anonymous posts expose no owner ID or private subject ID to others. Existing unchanged snapshots survive source edits/deletion. Publication requestId retries return the original post before revalidating a now-deleted source.
- `GET/POST /posts/:id/comments`, optional one block and requestId. Anonymous original authors stay anonymous in comments. First actual other-person answer creates one in-app notification. One-level replies remain enforced.
- `POST /posts/:id/accept {commentId}`. Question owner only, other-person answer only. One current accepted answer; same answer is idempotent. Replacing an answer never retracts earned points and never awards the same answerer another 50 points on that question. Real in-app acceptance notification links back to the authorized post route.
- `POST /posts/:id/blocks/:blockId/{solve,vote,clone,save-question,schedule}`. Solves/votes aggregate once per person/block; polls close 24 hours after publication. No community solve writes a private Attempt. Explicit question saving creates a copied Question plus a review ledger, exposed as bootstrap Question.savedToNotes/communityPostId. Card copying preserves type, masks and diagram and starts at AGAIN. Schedule import copies flexible periods only, skips fixed periods and conflicts, never overwrites; action key includes the chosen target date. Comment blocks use the same actions.
- `GET /community/profiles/:userId`, `PATCH /community/profile {visibility}`, `GET /community/following`. Student profiles omit school/real name; subject/grade/follower visibility enforced. Anonymous activity is excluded even from own public-profile preview (own activity remains `/posts?mine=1`). Counts come from persisted acceptance/clone activity; comment-card credit belongs to the commenter.
- `PATCH /community/cards/:id {public}`, `POST /community/cards/:id/clone`. Private/deleted cards cannot be copied by this public endpoint. New-card default publication is applied by a database trigger only after explicit cardsDefault opt-in, preserving older private cards.
- `POST /follow {userId,following?}` supports explicit idempotent state, default same-grade privacy, 20 follows/day first week and 50 afterward. Parents cannot use public student following. `POST /blocks {userId}` or `{postId}` supports anonymous-author blocking without disclosing identity and removes both follow directions.

Snapshots: QUESTION, CARD, MATERIAL, PHOTO, ESSAY, POLL, SCHEDULE, MATH; maximum five/post, four photos, one supported attachment/comment. Parent posts accept PHOTO/POLL only. Photo data must be actual JPEG/PNG/WebP, at most 650,000 encoded characters each, within the existing 3 MB request limit. Source card upload URLs are converted to owned image bytes so publication never grants access to a private upload path. MATERIAL shares a bounded contiguous source excerpt (2,000 characters, at most three sentence endings; decimal points are excluded). ESSAY scores are copied only from the publisher's actual matching attempt. Fixed schedule labels are redacted to 학교.

Verification uses `newAIHarness` and isolated scratch databases created only under the explicitly checked loopback PostgreSQL target. Tests cover canonical/ref rejection, school isolation, anonymous comment privacy, author blocking, snapshot edits after source deletion, poll deadline/one vote, zero private attempts, copied wrong-note markers, mask/type preservation, schedule idempotency, acceptance reward replacement, first-answer notification, follow constraints, public-card privacy/default and profile omissions.

Limits: no scheduled community digest/reminder infrastructure or external push transport exists in this server. Only actual first-answer and acceptance in-app notices are implemented; no push/digest delivery is claimed. School access is based on the registered profile school, not institution-verified membership. Hidden answers are a reveal affordance, not an exam secrecy boundary. No local runtime migration/restart or external message/post was performed by the backend leaf.
